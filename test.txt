Rendering; What is rendering?<br> How 2 capture flat img of some geometric repr (3d models)<br> How light interacts w scene to produce particular img<br> Input: 3d model such as polyg mesh -> select a viewpoint (camera POV) and render it -> output: 2d img (usually a bitmap)<br> How 2 do this? Seems like a daunting problem<br> Solu: think of how light works irl. All we see is the light reflecting off stuff<br> So most rendering algos is simulating “physics of light” in some way;  
Stuff we need to consider when rendering; • Goal: approximate how things look in the real world<br> • Light source: emits “photons”. Diff light sources behave diff, ex sun v lightbulb. Also since every obj/patch reflects light, we basically end up with many many “light sources” in img<br> • Surface geometry: reflects “photons”. Diff surfaces reflect light differently – rough surface like blanket v smooth reflective surface like metal alarm clock<br> • Camera sensor: receives “photons”. Diff sensors (le gasp) sense light differently. Human eyes =/= a camera. Need 2 think of how u want scene to look, what kind of sensor<br> Lots of things 2 consider!!;  
Simplification: ray optics (geometrical optics); Simulating every single photon is overkill so we consider the ray abstraction<br> Trace out possible paths a light ray can take in scene;  
2 families of rendering algos; Key diff is how they deal w the “visibility” problem -> how 2 determine whats visible from POV of camera<br> 2 most commonly used types: rasterization and raytracing<br> Produces similar imgs but the differences in algo has strong implications on what types of apps can use either perspective -> for instance if u hava scene w many diff objs overlapping, rasterization makes it so that u must project EVERY obj onto plane but in raytracing the first obj that the ray hits is just the one u render<br> Tho raytracing can b optimized 2 perform in real time, still is much slower than rasterization -> rasterization default for real time apps like game engines;  
Rasterization; For each triangle: “Which pixels are covered by this triangle?”<br> Project 3d mesh onto 2d flat plane -> spots that r covered r essentially how the obj looks from that pov<br> Lines that connect 3d mesh to 2d plane is like the rays of light, pixels that intersect these lines can “see” the 3d obj<br> Shortcut to simulating the light rays<br> For each object {<br> // find pixels that are<br> covered by the object (therefore which obj visible at a particular pixel)<br> }<br> Not just projecting points, u take the entire 3d shape and project that onto 2d plane/img;  
Raytracing; For each ray (pixel): “Which triangle is visible from this pixel?”<br> Beam a ray from origin (camera) through 2d plane and onto 3d mesh<br> Pixels that intersect w this ray like photons <br> For each pixel {<br> // find objects that are<br> visible to the pixel<br> }<br> The more rays the better, but becomes more computationally expensive<br> May cast multiple rays per pixel<br> No magic num, adjust according to requirement for quality and also time;
