Graphics processing units;Highly specialized chips designed to accelerate parts of graphics pipeline<br> Used in lots of viddy games, vr, ai, real time apps<br> Allows us to render imgs very quickly;  
Old v current gpus; Old: highly specialized, only a handful of common graphics operations like Floating pt, lin alg, evaluating shading models<br> 1990s running at 50MHz<br> 8MB VRAM<br> New: DRASTIC improvement<br> 10,000+ programmable CUDA cores<br> running at 1,600MHz<br> 24GB VRAM<br> does a lot more than just standard graphics stuff<br> Used for ml, scientific simulations, etc<br> The equivalent of 2000s supercomputer<br> Tho can b applied to many things, at the core its still designed for graphics stuff -> rendering, and in particular rasterization;  
Gpu workload; Input: 3d scene<br> Output: beautifully rendered img<br> Rasterization usu used for real time apps -> a reason why gpu designed specifically for rasterization<br> Real time raytracing is also a thing tho nowadays;  
Gpus and rasterization; Embarrassingly parallel problem! Each operation is independent basically and can b performed at once<br> Remember: 295 vector operations<br> For each pixel sample:<br> • Inside-outside test<br> • Barycentric interpolation<br> • Shading<br> • Texture mapping<br> …<br> • Massive throughput gains possible by leveraging parallelism<br> • Most common operations require linear algebra;  
GPUs are massively parallel linear algebra machines; Hardware itself is built to support large amts of parallel floating pt lin alg calculations<br> allowing thousands of vertices and pixels to be processed simultaneously;  
Programmable graphics pipeline stages; • Programmable “shader stages” carry out specific tasks<br> • Application: sets up scene parameters and sends vertex stream with attributes (written by user)<br> -> sends vertex stream<br> • Vertex shader: calculates vertex-wise stuff and passes the computed results<br> -> vertex stream -> primitive assembly -> primitive stream<br> [optional geometry shader that does rasterization]<br> -> primitive stream -> rasterizer -> pixel stream<br> • Fragment shader: does per-fragment (pixel) computations and passes output (colour of pixel) to framebuffer for storage<br> shader code written in domain specific lang. does parallel stream computations! Written in GLSL (C-like language) for OpenGL/WebGL;  
Application: setting up model-view-projection; The below transformations r all matrix transformations:<br> • Model transformation: transforms object to be rendered from its own coordinate frame (model space) to the world space, all objs made by artists all have their own coord frame thats diff from xyz after it gets placed into scene<br> • View transformation: transforms from world space to camera space (positioning the world within the camera’s frame of reference)<br> • Projection transformation: projects from camera space to clip space (projects onto 2d img plane); typically in “normalized device coordinates” (NDC) which is a −1,1 3 cube<br> • Also: send actual vertex attributes to GPU!;  
shaders; Shader takes in input and outputs stream of primitives<br> Shader programs based on c<br> Lang: GLSL<br> types of programs used in graphics rendering pipelines, especially in 3D graphics and game development.<br> not just "normal code" in the sense of general-purpose programming like Python or JavaScript<br> specialized programs written for GPUs to process rendering data and produce visual outputs.;  
Vertex Shader; Purpose: Processes the attributes of vertices (e.g., position, color, normal vectors) in 3D models.<br> Input: Individual vertices of a 3D object.<br> Output: Transformed vertices, typically in screen space, and any additional data to be passed to subsequent stages in the pipeline.<br> Common Tasks:<br> Transform vertex positions from object space to world space, and then to screen space using matrices (like Model-View-Projection matrices).<br> Apply lighting calculations.<br> Pass data (like texture coordinates or lighting information) to the pixel shader.;  
Pixel Shader (Fragment Shader); Purpose: Calculates the color and appearance of individual pixels (or fragments) on the screen.<br> Input: Interpolated data from the vertex shader, such as texture coordinates, colors, or normals.<br> Output: A final color value for the pixel.<br> Common Tasks:<br> Texture sampling (fetching colors from textures).;
