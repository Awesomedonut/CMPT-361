Mapping, measuring distances, etc<br> >Geometric modeling: representing, using, describ, basically doing stuff w shapes in computer -> doing stuff w shapes of objects and scenes<br> >What data structures (for representation/storage) and algos (for processing) we need to use<br> >1st virtual computational model of real world object: utah teapot (also ex of geo model);

Geometric modeling is hard!; >High level: geometric modelling all abt writing methods to create shapes<br> >“Oh making shapes doesnt seem that hard” WRONG!<br> >Due to sheer variety of shapes to represent, many diff data structures, methods r needed<br> >Ex: the 2982342743 diff parts needed for plane, from seatbelt to wing to wire, old buildings, organics like skin or leaves or hair, tinyyyy objs like fibres on sweater, nonsolid objs like cloud or water;  

2 types of geometric representation; >Implicit (Ex: distance field)<br> >Explicit (ex: polygon mesh, point cloud)<br> >Which to use depends on situation: adv and disadv;  

Implicit representations; >Represents a shape by mathematical eqn that points on surface must satisfy<br> >algebraic surfaces<br> >Implicitly defines the obj. Can think of as “signed distance function” (SDF) from the surface of the sphere, so how far the given point is from surface<br> >If eqn output = 0, point lies exactly on surface. If f(.) > 0, outside, if < 0, inside<br> >For more complex shapes difficult to tell what the shape is exactly by looking at eqn, can just feed it many inputs to get a sense of whats inside/outside, like closing ur eyes and feeling w hands<br> >Can consider this eqn as black box<br> >For sphere, very easy to use implicit but hard to define w explicit: 𝑓(𝑥,𝑦,𝑧) = 𝑥^2 + 𝑦^2 + 𝑧^2 − 1<br> >Challenge: given some random obj, not always clear what the mathematical relationship /eqn should be (ex chair), so coming up w eqn that accurately represents is hard;  

Implicit: constructive solid geometry (CSG); >Combine simple primitives using boolean operations so u can form complex shapes; can b difficult to come up w the implicit equations for these complex shapes but ez to just take bool oper of some primitives like spheres and cubes<br> >Union (∪): merge two objects<br> >Difference (−): subtract one object from another<br> >Intersection (∩): take parts common to two objects<br> >Good when combinations of simple geometries are sufficient<br> >Commonly used in manufacturing software;  

Explicit repre; >Implicit can b difficult for computer apps like rendering, so we often turn to explicit<br> >Data structures that explicitly tell u pts that lie on surface of obj<br> >Literally just a big list of points that r on surface, no “guess and test”, no need to “construct formu that gives rise” to these points <- point cloud, simplest way to implement<br> >Sphere: sample some pts from (cos 𝜃 sin 𝜙, sin 𝜃 sin 𝜙, cos 𝜙) for 0 ≤ 𝜃 < 2𝜋, 0 ≤ 𝜙 ≤ 𝜋<br> >^just an ex. U dont actually need any func/formu<br> >Can use for 2d as well: points lie on edge of shape<br> >Often used for more complex objs<br> >Conceptually explicit repr uses v simple data structure, but actually creating ur data can require a lot of work;  

Implicit v explicit: computational tradeoffs; >Possible to convert between these 2 repres<br> >Implicit representations<br> + Inside/outside test is easy since its literally just plug and chug. Useful for stuff like physics simulations where u need to see if 2 objs collided or not<br> + Efficient representation since its just an eqn<br> + “Infinite resolution” for simple shapes bc the more u zoom u can just plug and chug<br> - Hard to model complex geometries bc equations r hard to figure out for this kind of stuff<br> - Hard to efficiently sample points on surface. BIG problem for rendering bc u need to know the pts on the surface so u can do stuff with it like map to 2d plane/camera<br> >Explicit representations<br> + Easier to model arbitrarily complex geometries bc u can just add pts to the pt cloud<br> + Easier to sample points on surface, just trivial to take some pts u have stored in ur data structure<br> - Inside/outside test is harder<br> - Usually “finite resolution” since u have finite, discrete set of points. Once u zoom to a certain point ull def see discretization;
