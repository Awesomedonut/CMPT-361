storing img in computer memory; >after u decide on what repr to use, need a way to store:<br> >Framebuffer: continuous area of memory storing image. Its just a data structure that stores array of numbers (we think of img as 2d grid/matrix, then it gets flattened and stored)<br> >along w pixel colour nums, may also store some metadata such as dimensions of img<br> >Resolution: spatial dimensions - num of pixels along width & height of img (e.g., 1920 x 1080 “HD”) stored in this framebuffer<br> >also need 2 decide Depth (or precision) of pixels: how many bits do we use to represent the colour of each pixel<br> >(e.g., 1-bit monochromatic, 24-bit RGB) num of bits determines range of vals (num of colours we can use for all the colours of og object)<br> >common design: 24 bits to represent all 3 channels, so 8 bits for each channel. Ie 24 bits per pixel<br> >8 bits: 2^8 = 256 discrete values for each channel, ie 256 possible red values<br> >more bits = more granular = less pixelated<br> >most imgs we use in this course uses Rgb bitmap<br> >can use any num of bits for each channel;  

display technologies; >CRTs (Cathode Ray Tube)<br> >largely replaced<br> >one of the OGs<br> >lots of concepts of this kind of tech originates from it so worth learning abt even if its largely deprecated<br> >used by those old bulky TVs<br> >basically works by having an electron gun that needs to shoot at the spot of every pixel on a phosphorous screen (u have to scan it – raster scan)<br> >the reaction makes a colour for rgb, controls ratio of rgb basically by how many electrons u shoot at it. The direction of the gun is steered by how much voltage u pass thru and these deflectors control the trajectory<br> >Fps/refresh rate is limited by the hardware bc u physically need to shoot every pixel to update the frame, which is kinda oh no when u wanna do videos;  

Video display; >Flicker fusion rate: frequency at which flickering light appears steady to a human observer<br> >all display tech takes advantage of this fact abt human perception<br> >Fool human eye into thinking pics are moving if u go beyond threshold (any amt is fine, if u keep increasing fps human will still just perceive as moving, but wont notice diff - at that point humans cant perceive the changes in images anymore)<br> >rate changes depending on lighting<br> >In high ambient light & large field of view: 80 Hz<br> >In low ambient light: 20-30 Hz<br> >Film 24 fps<br> >Television (interlaced) 30 fps<br> >Computer (progressive) 60 fps<br> >interlace v progressive: electron gun only shoots half of the pixels each time for interlaced, “hack” to counteract crt’s slowness<br> >By virtue of updating fewer pixels each time it allows u make it seem like ur doubling framerate<br> >Introduces artifacts<br> >Dimmer lighting helps ppl not see those artifacts as much<br> >prog updates all pixels each time (lack of interlacing). Modern display tech uses prog;  

LCD: liquid crystal displays/LED; >main limitation of CRT is low refresh rate<br> >mostly replaced by LCD<br> >LED LCD: light emitting diode LCD<br> >basically how it works is there r a bunch of layers.<br> >U start off w backlight which is just a neutral white light -> pass thru polarization layer which blocks light from every direction except 1 (so it makes sure the light is all in 1 direction) -> then pass thru liquid crystal layer, using voltages to change dir. U cna have diff voltages at diff points on this layer, and accordingly the dir varies (so its not all uniform in 1 dir) -> then pass thru another polarization layer which is a diff dir, if w/o the liquid crystal layer to change dir then they would all b filtered out -> lastly go to screen which has colour filters to control rgb vals that human will see;

Liquid crystal v CRT; >LCD Much more compact than CRT since all layers can b made of v thin material (phones r tinyyyy) v CRTs which need to contain electron gun<br> >Much faster refresh rate (240 Hz) since electron gun doesnt have to scan all pixels<br> >basically lcd works by filtering the backlight so most of that light is actually wasted since ppl arent even gonna see it (inefficiency)<br> >also the filters arent perfect, each pixel will also always have a bit of light leakage. So Can’t turn a pixel off completely -> No way to truly display black<br> >some limitations in display of colours (may b not as good as CRT);  

OLED; >Organic Light Emitting Diode<br> >wont go into deets for this class<br> >no backlight, LED elements emit their own light individually<br> >improves img contrast;
